# Multi-Teacher On-Policy Distillation (MOPD)

## Motivation

Reinforcement learning can improve a large language model's capabilities in a specific domain, such as math, software engineering, or question answering. Combining these capabilities in a single model remains a challenge.

Previous approaches have different limitations:

- **Sequential RL:** Training on one domain after another can weaken capabilities learned earlier.
- **Weight merging:** Averaging the weights of expert models can produce an unstable model that fails to retain all of their capabilities.
- **Off-policy supervised fine-tuning:** Training a student on the outputs of domain-specific RL teachers can cause exposure bias, since the student does not train on its own responses.

MOPD addresses these issues by training domain experts separately and distilling their capabilities into a single student model.

## Setup

Multi-teacher on-policy distillation is a post-training method that combines the capabilities of multiple RL teachers, each specializing in a particular domain. MOPD first performs specialized RL in each domain to obtain a set of specialist teachers. Their capabilities are then distilled into a single student model through on-policy distillation.

This approach has several benefits:

- Provides a dense optimization signal.
- Avoids exposure bias because rollouts are generated by the student.
- Integrates capabilities in policy space instead of weight space, which makes training more stable.

> [!note]- What is on-policy distillation?
> The student generates a response and receives token-level feedback from the teacher at each position. Repeating this process lets the student learn from its current mistakes and reduces exposure bias.
>
> Given a prompt $x$ and a student-generated response $y$, the on-policy distillation loss is:
>
> $$
> \mathcal{L}_{\mathrm{OD}}(\theta)
> := \mathbb{E}_{x\sim\mathcal{X}}\left[
> \mathbb{E}_{y\sim p_S(\cdot\mid x)}\left[
> D_{\mathrm{KL}}\!\left(p_T\|p_S^\theta\right)(y\mid x)
> \right]\right].
> $$
>
> The KL divergence compares the teacher and student next-token distributions along the sampled response. We do not backpropagate through the student's sampling distribution $p_S(\cdot\mid x)$ for stability.

## Method

MOPD runs in three stages:

1. **General SFT:** The pretrained base model is fine-tuned on a large corpus of data that covers all base capabilities. This SFT checkpoint serves as the starting point for the domain-specialized RL training that follows.
2. **Domain-specialized RL training:** In this stage, we train a domain expert $\pi_{\phi_d}$ for each domain $d$, starting from the SFT checkpoint. The per-domain training runs are independent and can run in parallel.
3. **MOPD:** The student is initialized from the base SFT checkpoint, while the domain experts are frozen and form a teacher group. We then train the student on a multi-domain dataset in the following steps:

   1. Sample a prompt from the multi-domain dataset.
   2. Route it to the matching teacher.
   3. Obtain a rollout from the student.
   4. Prefill the teacher on the rollout to get token-level feedback.
   5. Update the student using the teacher signal.

## Equation

The student is optimized using the per-token reverse KL divergence between its predictions and those of the domain teacher.

$$
\mathcal{L}_{\mathrm{rev\text{-}KL}}(\theta)
= \mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta(\cdot\mid x)}\left[
\frac{1}{|y|}\sum_{t=1}^{|y|}\sum_{v\in\mathcal{V}}
\pi_\theta(v\mid x,y_{<t})
\log\frac{\pi_\theta(v\mid x,y_{<t})}{\pi_{\phi_d}(v\mid x,y_{<t})}
\right].
$$

Here, $d$ is the domain of prompt $x$, and $\pi_{\phi_d}$ is its corresponding domain expert.

## Policy Gradient Formulation

The gradient of the per-token reverse KL divergence is given by:

$$
\nabla_\theta \mathcal{L}_{\mathrm{rev\text{-}KL}}(\theta)
= -\mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta(\cdot\mid x)}\left[
\frac{1}{|y|}\sum_{t=1}^{|y|}
\log\frac{\pi_{\phi_d}(y_t\mid x,y_{<t})}{\pi_\theta(y_t\mid x,y_{<t})}
\nabla_\theta\log\pi_\theta(y_t\mid x,y_{<t})
\right].
$$

This has the same form as the policy gradient equation:

$$
g = \nabla_\theta J(\theta)
= \mathbb{E}_{\tau \sim p_\theta}\left[
\sum_{t=0}^{T-1}\Psi_t \cdot \nabla_\theta\log\pi_\theta(a_t \mid s_t)
\right].
$$

In MOPD, the trajectory $\tau$ is the student-generated response $y$, the state is the prompt and generated prefix $s_t=(x,y_{<t})$, and the action is the next token $a_t=y_t$.

The teacher–student log difference acts as a per-token *advantage*:

$$
\hat{A}_{\mathrm{MOPD},t}
= \operatorname{stopgrad}\!\left[\log\pi_{\phi_d}(y_t\mid x,y_{<t})-\log\pi_\theta(y_t\mid x,y_{<t})\right].
$$

For training stability, the advantage is clipped on both sides:

$$
\hat{A}^{\mathrm{clip}}_{\mathrm{MOPD},t}
= \operatorname{clip}\!\left(\hat{A}_{\mathrm{MOPD},t},-A_{\max},+A_{\max}\right).
$$

This gives the loss:

$$
\mathcal{L}^{\mathrm{PG}}_{\mathrm{MOPD}}(\theta)
= -\mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta(\cdot\mid x)}\left[
\frac{1}{|y|}\sum_{t=1}^{|y|}
\hat{A}^{\mathrm{clip}}_{\mathrm{MOPD},t}
\log\pi_\theta(y_t\mid x,y_{<t})
\right].
$$

This form can be used in existing PPO/GRPO implementations. The only difference is how the advantage is computed.

## Top-K Distillation

We can distill the teacher's top-$k$ tokens as a lower-variance alternative. Let the teacher's top-$k$ token set at position $t$ be:

$$
\mathcal{T}_t^d = \operatorname{TopK}_k\!\left(\pi_{\phi_d}(\cdot\mid x,y_{<t})\right).
$$

We then use the following loss:

$$
\mathcal{L}_{\mathrm{MOPD}}^{\mathrm{TopK}}(\theta)=\mathbb{E}_{x\sim\mathcal{D},\,y\sim\pi_\theta(\cdot\mid x)}\left[\frac{1}{|y|}\sum_{t=1}^{|y|}\sum_{v\in\mathcal{T}_t^d}\left(\pi_\theta(v)\log\frac{\pi_\theta(v)}{\pi_{\phi_d}(v)}-\pi_\theta(v)+\pi_{\phi_d}(v)\right)\right].
$$

Here, $\pi_\theta(v)$ and $\pi_{\phi_d}(v)$ are conditioned on $(x,y_{<t})$. The loss is minimized when $\pi_\theta(v)$ and $\pi_{\phi_d}(v)$ are equal for the selected tokens.

## SDPO vs MOPD

| Aspect             | SDPO                                                     | MOPD                                                                   |
| ------------------ | -------------------------------------------------------- | ---------------------------------------------------------------------- |
| Teacher            | The current policy prompted with feedback                | Separate, frozen domain experts trained with RL                        |
| Teacher signal     | How feedback changes the policy's next-token predictions | How a domain expert's next-token predictions differ from the student's |
| Training responses | Generated by the student                                 | Generated by the student                                               |
| Main goal          | Learn from feedback on the student's own attempts        | Combine several domain experts into one student                        |

## Limitations

MOPD depends on the student and each teacher having similar policy distributions. In the paper, replacing a same-origin teacher with a larger but less aligned model led to training instability and reduced performance.

MOPD routes each prompt to a single domain teacher. For problems that span multiple domains, it is unclear whether one teacher can provide enough guidance.

## Conclusion

Multi-Teacher On-Policy Distillation (MOPD) is a post-training procedure that distills multiple domain experts into one model. The student generates a rollout, the prompt is routed to its corresponding domain teacher, and that teacher provides token-level feedback. The policy-gradient and top-$k$ implementations perform comparably, and same-origin teachers are crucial for stable optimization.
